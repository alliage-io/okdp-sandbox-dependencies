# rustfs

OKDP chart of [RustFS](https://rustfs.com), a single-node S3-compatible object
store: an alternative to [`seaweedfs`](../seaweedfs) as the platform object store (one
pod, no filer/master/volume split). Buckets, S3 identities, policies and OIDC sign-in on
the console are provisioned from its parameters. It **provides** an `s3` connection and
consumes none.

Deployed as the release `default-storage` (component `20-storage`), it serves the same
hosts and the same connection values as seaweedfs (`ci/sandbox-values.yaml`), except
`internalUrl` (`http://default-storage-svc.default.svc.cluster.local:9000`): the two are
mutually exclusive.

The former KuboCD modules are vendored upstream charts (`vendor.yaml`,
`vendor/`) rendered by `okdp.vendor.render` with computed values
(`templates/_values.tpl`):

| Former module | Now | Rendered when |
|---|---|---|
| `main` | `vendor/rustfs` (rustfs 1.0.0), standalone mode | always |
| `main` extraManifests: ingresses | `templates/ingress.yaml` (S3 API and console) | always |
| `main` extraManifests: provisioning | `templates/provision.yaml` (ConfigMap + post-install/post-upgrade Job) | always |
| `oidc-dcr` | `vendor/oidc-dcr` 0.3.3 (pre-install/pre-upgrade hook) | `global.okdp.oidc.clientProvisioning: dcr` |
| - | `templates/root-secret.yaml`: root identity generated by ESO | `rootSecretKey` empty |

## Parameters

| Parameter | Default | Description |
|---|---|---|
| `rootAccessKey` | `okdpadmin` | Access key of the root identity (3-20 characters). |
| `rootSecretKey` | `""` | Its secret key (8-40 characters). Empty: generated once by an ESO Password generator into Secret `<release>-root`. A value set here is stored in Git. |
| `consoleHost` / `apiHost` | `<instance>-<ns>` / `<instance>-<ns>-api` | Host names; the ingress suffix is appended. |
| `dataStorage` | `5Gi` | Data volume size. |
| `caBundleSecret` | `certs-bundle` | Secret holding `ca.crt`, trusted when calling the OIDC issuer. |
| `memoryGi` | `2` | Memory limit (GiB). |
| `cpu` | `0.25` | CPU request (vCPU); the limit is twice this value. |
| `grants[]` | `[]` | `{principal, credentialsSecret: {name, accessKeyKey, secretKeyKey}, actions?, buckets?, sts?}`: one S3 identity per consumer, keys read from a Secret of the namespace. `actions` are neutral verbs (`read`, `list`, `write`, `admin`, any case); `admin` or `sts: true` attaches `consoleAdmin`. |
| `buckets[]` | `[]` | `{name, anonymousRead?, paths?}`: buckets created at startup; `paths` seeds empty prefixes. |
| `oidcPolicies[]` | `[]` | `{name, actions?, buckets?}`: policies named after the values of the policy claim. |
| `oidcPolicyClaim` | `groups` | Claim carrying the policy names; every value must name an existing policy or the login is refused. |
| `oidcPolicyScope` | `""` | Scope requested on top of the platform scopes so that claim is issued (dcr mode). |
| `outputSecretRef` | `""` | `secretRef` of the published connection: an identity of this store (a grant's `credentialsSecret`). Empty: `<release>-s3-credentials`, generated by ESO and provisioned with read, list and write on every bucket. |

Platform values read (`global.okdp`): `ingress.suffix`, `ingress.className`,
`certificateIssuers.selfSigned.name`, `storageClass.data`,
`oidc.{enabled,issuerUri,displayName,scope,clientProvisioning,dcr}`. Needs ESO
(component `00-external-secrets`, `external-secrets.io/v1`) for the generated Secrets.

Secrets expected in the namespace: the `credentialsSecret` of every grant; when
OIDC is on, `creds-<release>-oauth2` (`client_id`/`client_secret`, when
`clientProvisioning` is `existing`) and the CA bundle. In `dcr` mode the
registration job writes `<release>-<namespace>-dcr` with the same keys.

Endpoints (`<instance>` is the release name without its `<project>-` prefix):

- S3 API: `https://<instance>-<namespace>-api.<suffix>` (or `apiHost`)
- Console: `https://<instance>-<namespace>.<suffix>` (or `consoleHost`; the descriptor `url`)
- In-cluster: `http://<release>-svc.<namespace>.svc.cluster.local:9000`

Provisioning (`templates/provision.yaml`) is a post-install/post-upgrade hook Job,
idempotent, re-run on every sync. It runs the store's own image (`rustfs/rustfs`, same
tag as the server): `curl` signs its requests (SigV4) with the root identity, the S3 API
creates the buckets (with the anonymous download policy when `anonymousRead`) and the
`.keep` markers of `paths`, and the RustFS admin API (`/rustfs/admin/v3`, plain JSON)
creates or updates the users and policies of the grants, of the s3 output and of
`oidcPolicies`. It replaces the MinIO client (`quay.io/minio/mc`, archived).

OIDC sign-in on the console is configured in the server's environment
(`RUSTFS_IDENTITY_OPENID_*`, the client ID and secret read from the OAuth client
Secret), so it works from the first start. RustFS discovers the provider at startup
only: if the issuer was unreachable then, the sign-in button stays off until
`kubectl -n <namespace> rollout restart deploy/<release>`.

## Upstream values

Any value of the vendored `rustfs` chart can be set per instance under
`upstream.rustfs`, merged over the values computed from the parameters
(okdp-lib-chart `okdp.vendor.render`, option `upstream`):

```yaml
upstream:
  rustfs:
    image: {rustfs: {repository: mirror.example.org/rustfs/rustfs}}
    tolerations: [{key: dedicated, operator: Exists, effect: NoSchedule}]
    config: {rustfs: {log_level: debug}}
    extraEnv: [{name: EXTRA_FLAG, value: "1"}]   # appended to the chart's env
```

The paths the platform relies on are refused, and the lists carrying the OIDC
client Secret and the CA bundle are appended to rather than replaced: see
`okdp-rustfs.upstream.rustfs` in `templates/_values.tpl` (also listed in the
schema description). An upstream value wins over the parameter it overlaps
(`resources.limits.memory` over `memoryGi`). No key or value may contain `{{`
(the schema and okdp-lib-chart both refuse it). `oidc-dcr` takes no upstream
values.

## Provided connection

The descriptor (`<release>-okdp`, `outputs.yaml`) publishes `<release>`
(contract `s3`):

```yaml
apiUrl: https://<instance>-<namespace>-api.<suffix>
internalUrl: http://<release>-svc.<namespace>.svc.cluster.local:9000
consoleUrl: https://<instance>-<namespace>.<suffix>
region: us-east-1
pathStyle: true
secretRef: {name: <outputSecretRef|release-s3-credentials>}
```

With `outputSecretRef` empty, `<release>-s3-credentials` (`accessKey`/`secretKey`) is
generated by ESO and provisioned as an identity with read, list and write on every
bucket (policy `okdp-s3-credentials`). Set, it names a grant's Secret and nothing more is
generated (the sandbox publishes `creds-seaweedfs-s3`, the `platformAdmin` grant).

**`s3` is an external-only contract.** A consumer cannot reference this
instance by release name (`okdp.connection` has no internal convention for
`s3`: a store usually lives in another namespace than its consumers). A
project that uses this store declares a connection file,
`projects/<project>/connections/<name>.yaml`, with the fields above (the
console fills them from the descriptor output) and a `secretRef` to a Secret
of the consumer's namespace. That Secret is the consumer's own identity: a
`grants[]` entry of this store, delivered into the consumer namespace by ESO
when the store lives elsewhere. Most consumer charts also take an
`s3SecretRef` parameter for it.

```yaml
# projects/demo/connections/storage.yaml
connections:
  storage:
    contract: s3
    apiUrl: https://storage-default-api.okdp.sandbox
    internalUrl: http://default-storage-svc.default.svc.cluster.local:9000
    region: us-east-1
    pathStyle: true
    secretRef: {name: creds-demo-s3}
```

## Uninstalling

- The data and log volumes carry `helm.sh/resource-policy: keep` (upstream):
  delete the PVCs `<release>-data` and `<release>-logs` by hand to drop the data.
- In `dcr` mode the registered OAuth client is **not** unregistered: the former
  cleanup relied on a `pre-delete` hook, which Argo CD does not run. Unregister
  it with the token the registration job stored, then delete the Secret (it is
  not owned by the release):

  ```sh
  ns=<namespace>; secret=<release>-<namespace>-dcr
  uri=$(kubectl -n "$ns" get secret "$secret" -o jsonpath='{.data.registration_client_uri}' | base64 -d)
  rat=$(kubectl -n "$ns" get secret "$secret" -o jsonpath='{.data.registration_access_token}' | base64 -d)
  curl -sS --cacert ca.crt -X DELETE -H "Authorization: Bearer $rat" "$uri"
  kubectl -n "$ns" delete secret "$secret"
  ```

  Or delete the client `<instance>-<namespace>` in the provider's admin console.

## Changes from the KuboCD package

- The s3 output is named after the release (was `s3`, Connection
  `kcd-<release>-s3`) and now carries a `secretRef`: generated credentials, or
  `outputSecretRef` (new).
- Hosts can be set (`consoleHost`, `apiHost`, new).
- `rootSecretKey` is optional: empty, the root key is generated by ESO (was
  required, stored in the Release).
- Resources are named after the Helm release `<project>-<instance>` (the
  former KuboCD release name for a platform store such as `storage`): the
  Service, the PVCs and the Secrets change name. Moving an existing store means
  copying its data.
- The provisioning job runs the RustFS image with `curl` (was the MinIO client, `mc`,
  and the `mcImage` parameter); a changed policy is now updated on the next sync (was
  created once). Grant keys are passed to it as `G<index>_AK`/`G<index>_SK`, so any
  principal name works.
- OIDC is set in the server's environment (was `mc admin config set identity_openid`
  from the job, which needed a restart after the first install).
- Ingresses and the provisioning job are templates of this chart (were upstream
  `extraManifests`); the ingress class comes from
  `global.okdp.ingress.className` (was hardcoded `nginx`).
- The DCR Job, its ConfigMap, ServiceAccount, Role and RoleBinding are
  `<release>-oidc-dcr` (upstream: `dcr` and `oidc-dcr`, shared by every DCR client
  of the namespace; `okdp.vendor.oidcDcr`).
